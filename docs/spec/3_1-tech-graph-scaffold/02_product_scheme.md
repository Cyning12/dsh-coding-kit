# 02 · 三轨产品方案

> **状态**：`draft` · 隶属 `3_1-tech-graph-scaffold`

---

## 1. 总览

| 轨 | 中文名 | 本版职责 | 对应波（见 04） |
|----|--------|----------|----------------|
| **A 内容生成** | 脚手架 | 接入后直接写出可审草稿 YAML/模块表 | W1（核心） |
| **B 保真** | 存在性 + 漂移 | 生成后锚点/模块可证伪；后续代码变更可机检漂移 | W1 附 + W3 |
| **C 覆盖** | 档位 + 词表 | 首份只保 L0+L1+≥1×L2；仓级边型可扩展 | W1 档位 + W4 |

模板轨：**暂不扩**。脚手架写内容时以**真实仓结构**为源；仅协议文件（如 `99_mermaid_protocol.md`）允许从包内原样复制。

## 2. 轨 A · 内容生成（脚手架）

### 2.1 输入

- `--target` 业务仓根（须 git 仓，沿用既有纪律）  
- 可选：`--input` 输出目录（缺省 `docs/_tech_graph`）  
- 可选：栈提示（如 `auto` / `node` / `python`）；缺省 `auto` 探测  
- 可选：`--mode full|struct-only`（缺省 `full` · 见 §4.1）  
- 可选：`--strict`（轻检咬 exit 2 · 见 03）  

### 2.2 探测启发式（首版最小集 · 可测）

| 信号 | 用途 |
|------|------|
| 顶层目录名（如 `src/` `app/` `api/` `lib/` `packages/`） | 推断 `01_struct` 一级模块行（3～12 行上限） |
| 入口候选（如 `package.json#main`、常见 `src/index.*`、`app/**/page.*`、`**/main.py`） | `00_main` 入口节点锚点 |
| 路由/处理器浅扫（上限见下表） | 主流程节点草稿；超限则截断并写入清单「已截断 / 待补」 |
| 无法探测 | 仍写出草稿，锚点标 `TBD`，stderr/清单明示缺口 |

**浅扫上限（2026-10-10 维护者裁决 · 消解 20 审 A5 · W1 测锁）**：

| 参数 | 初值 | 触顶行为 |
|------|------|----------|
| 最大目录深度 | **4** | 停止向更深目录扩展 |
| 最大扫描文件数 | **200** | 停止继续打开文件 |
| 主流程最大节点数 | **16** | 超出节点进「待补清单」，不继续膨胀 YAML |

触顶 **不** 视为失败（exit 0）；须在 `REVIEW_CHECKLIST.md` 标明截断事实，便于人/Agent 补全。

### 2.3 输出（「直接生成一份」的钉死集合）

| 文件 | 要求 |
|------|------|
| `00_main.graph.yaml` | 入口 → 主路径 → 子图指针；锚点尽量真实，否则 `TBD` |
| `01_struct.md` | 真实模块行；**删除**模板示例行；人签表 status=`pending` |
| `10_flow_<slug>.graph.yaml` | ≥1 条；slug 可 `MAIN` 或探测名 |
| `99_mermaid_protocol.md` | 包内协议原样（或等价指针） |
| `02_version.md` | 可选；有 `CHANGELOG`/`package.json` version 则写一行种子 |
| 审核清单 | **唯一** `REVIEW_CHECKLIST.md`（见 [`03_cli_and_review.md`](./03_cli_and_review.md)） |

写盘策略：

- 目标已存在且非空：默认 **拒写**（exit 2）+ 提示；显式 `--overwrite-draft` 仅覆盖带草稿标记的文件（实现波定精确语义）。  
- **永不**静默覆盖已人签 / 无草稿标记的语料。

### 2.4 与「自动生图」禁令的划界

| 允许 | 禁止 |
|------|------|
| 目录/入口启发式生成**草稿** | 声称覆盖全业务语义 |
| 截断 + 待补清单 | 无上限递归全仓 AST |
| 人/Agent 改 YAML 后重编译 | 自动改 `HG-GRAPH-MODULES` → approved |

## 3. 轨 B · 保真

### 3.1 生成后轻检（W1 必带）

- 模块表 glob 是否命中 ≥1 文件  
- 硬边锚点 `path` 是否存在（`TBD` 不计失败，计入清单「待补」）  
- 产出后自动或链式调用 `graph yaml compile`（失败则脚手架整体失败）  

### 3.2 漂移闸（W3 · 承接 3.0.2 F-2）

命令面示意：`graph drift`（精确用法见 03 / PLAN）。

最小可验收语义（MVP）：

- 一级模块目录/包路径须出现在 `01_struct`（可配置白名单）  
- 已登记锚点 path 消失 → 报漂移  
- 不试图「自动重画」；只报告，退出码可入 CI  

## 4. 轨 C · 覆盖

### 4.1 档位（沿用 ONBOARDING S0～S3 精神）

| 档位 | 如何触发 | 脚手架覆盖 |
|------|----------|------------|
| 新仓 / S0 | `--mode full`（**缺省**） | L0 + L1 + ≥1 主流程 |
| 存量 S2+ | **显式** `--mode struct-only`（2026-10-10 裁决 · 消解 20 审 A4 · **不**靠自动探测猜档位） | 模块表 + 待补流程清单；不强制写 `10_flow_*.graph.yaml` |

### 4.2 仓级词表（W4 · 承接 3.0.2 F-1②）

- 路径约定：`.spec-wave/graph-vocab.yaml`（与消费侧配置目录同族）  
- 与内置 `assets/tech-graph-vocab.yaml` **合并**；冲突 fail-loud  
- 「登记 ≠ 封闭」惯例不回退：未登记显式 type 仍 Warning 不咬 exit
