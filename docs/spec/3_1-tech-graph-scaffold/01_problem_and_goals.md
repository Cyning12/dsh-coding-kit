# 01 · 问题与目标

> **状态**：`draft` · 隶属 `3_1-tech-graph-scaffold`

---

## 1. 问题陈述

现行业务仓技术图谱路径是：

1. 手工复制 `assets/graph/templates/` → `docs/_tech_graph/`  
2. 人 / Agent 改写占位锚点与模块表  
3. `graph yaml compile|export|check`  
4. 人签 `HG-GRAPH-MODULES`

痛点：

| # | 痛点 | 后果 |
|---|------|------|
| P1 | **只有模板**，无自动化内容生成 | 新仓入手慢；占位路径（如示例 `src/main.py`）与真仓不符 |
| P2 | 模板扩写不能解决「准」 | 业务栈各异；扩模板只会堆假锚点 |
| P3 | 缺保真机检 | 草稿与代码漂移只能靠肉眼（3.0.2 已记 F-2 延后） |
| P4 | 仓级边型词表不可扩展 | 消费仓合法边型只能挤内置登记或吃告警疲劳（F-1② 延后） |
| P5 | 审核入口分散 | 人与 Agent 缺少同一份「审什么」清单 |

历史 bootstrap 任务模板曾写「不做全仓代码扫描自动生图」——本 SPEC **收窄该禁令**：允许**受约束的脚手架草稿**（目录/入口探测 → 提议节点边）；**仍禁止**把自动产出直接当作已签收真值，或一次画完全仓流程。

## 2. 完成态行为（消费者可观察）

接入 SpecWave 的业务仓（git 仓根）在维护者执行脚手架后：

1. **存在** `docs/_tech_graph/`，且至少包含：  
   - `00_main.graph.yaml`（及编译后的 `00_main.md`）  
   - `01_struct.md`（一级模块表，来自真实目录推断，非模板示例行）  
   - ≥1 条 `10_flow_*.graph.yaml`（主路径草稿）  
   - `99_mermaid_protocol.md`（协议原文落入，不扩业务语义）  
2. 产物带 **草稿标记**（文件头注释或 frontmatter / 旁路清单明确 `status: draft`）。  
3. 可跑通既有 `graph yaml compile` → `export` → `check`（exit 0 或仅开放惯例 Warning）。  
4. 提供**同一审核面**：人可读清单 + Agent 可跑检查项（锚点存在性、模块 glob 命中、禁止自动人签）。  
5. `HG-GRAPH-MODULES` **仍为 pending**，直到维护者人签；签后方可挡 30 改码（既有纪律不变）。  
6. 后续可选：漂移闸（F-2）、仓级词表（F-1②）在 CI / 本地可跑。

## 3. 成功判据（产品级）

| 角色 | 成功长什么样 |
|------|----------------|
| 新人维护者 | 接入后一条命令（或等价 Agent 技能）得到可打开的图谱草稿，不必先手抄模板 |
| 审查人 | 打开清单即可勾「模块像不像 / 主路径对不对 / 锚点是否瞎编」 |
| Agent | 同一清单可机械复跑；改 YAML 后再 compile/check |
| 既有用户 | 旧命令行为不变；可选启用新命令 |

## 4. 非目标（再强调）

- 不扩模板包业务占位内容。  
- 不自动 approved 任何人闸。  
- 不做全仓子流程一次生成。  
- 不做可视化编辑器。
